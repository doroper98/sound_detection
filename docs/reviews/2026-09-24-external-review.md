# SoundField Lab 외부 검토 결과와 다음 작업 지시

- 검토 대상: `main` 커밋 `fa85c39` (빌드 10 병합 시점)
- 검토 범위: 웹(TypeScript 약 1,900줄), 네이티브(Swift 약 4,000줄), 문서(약 1,500줄), CI 4종
- 번호 규약: 기존 마지막 항목(REQ-NATIVE-027 / SC-49, EXP-022, BUG-023) 다음부터 이어 붙인다
- 이 지시는 최종 점검을 거쳤다. 목표와 무관한 정리 작업은 의도적으로 제외했다(9절)

## 1. 총평

유지할 것은 유지한다. 가상/합성/실기기 구분, 엔진 분리, 증거 JSON 보존, FOA 경로 발견은 그대로 간다.

문제는 하나다. **빌드 10개 동안 실기기 위치 정확도가 0건 확인이다.** 원인은 알고리즘이 아니라 작업 루프다.

현재 루프: 빌드 → 실기기 실패 → 통계 JSON만 남음 → 원인 미확정 → 문서화 → 다음 빌드.

통계만 남기는 설계(NFR-001) 때문에 실패 원인을 소급 분석할 수 없었다. 빌드 7·8·9 분석이 전부 "PCM이 없어 확정 불가"로 끝난 것이 증거다.

루프를 바꾼다. **계측(원음 저장) → 정답 데이터셋 → 오프라인 알고리즘 반복 → 판정 → 빌드.** 새 IPA는 P0가 끝나기 전에 만들지 않는다.

## 2. 작업 규칙 (이 지시 전체에 적용)

- P0-1, P0-2 완료 전 새 빌드·새 UI 기능 금지. "새 빌드로 확인하자"를 반복하지 않는다.
- 실패 기록마다 두 줄을 반드시 적는다. "다음 측정으로 확정 가능한가: Y/N", "필요한 데이터: <파일명>".
- 성능 주장은 숫자로 쓴다. "개선" 대신 "방위 MAE 12.3°→6.1°, n=45".
- 리팩터 커밋과 기능 커밋을 분리한다. 리팩터 커밋은 동작 변화 0을 기존 테스트로 증명한다.
- 합성 PASS를 실기기 PASS로 적지 않는 기존 규칙은 그대로 둔다.
- 각 REQ의 완료 증거는 `docs/reports/` JSON + CI run URL 한 쌍이다.
- GOAL.md에는 요구사항표만 추가한다. 빌드 이력·검증 서술은 DEVLOG.md에만 쓴다. 기존 이력의 이동은 선택이다.
- 기존 파일을 스타일 이유로 재포맷하지 않는다. 새로 쓰는 코드만 한 줄 한 문장으로 쓴다.

## 3. P0 — 지금 막혀 있는 것을 푼다

### P0-1. 연구 모드 원음 저장 — REQ-NATIVE-028 / SC-50

목적: 실패한 세션을 노트북에서 다시 분석할 수 있게 한다.

구현:
- `FOACapture.swift`에 opt-in 플래그 `researchRecording`을 둔다. 기본 OFF. 켜진 동안 화면에 빨간 REC 표시를 유지한다.
- 저장 항목(세션 폴더 하나):
  - `foa.wav` — 4채널 Float32, ACN/SN3D W,Y,Z,X 순서 그대로. 필수.
  - `pose.jsonl` — AR 프레임별 timestamp·quaternion·position. 필수.
  - `manifest.json` — 빌드 번호, 기기 모델, 샘플률, layoutTag, 시작 hostTime, 각 파일 SHA-256, 사용자 라벨, 정답 각도(P0-3). 필수.
  - `stereo.wav` — 2채널. 선택.
- 저장 위치는 앱 Documents. 내보내기는 **기존 공유 시트를 재사용**한다. Files 앱 노출(`UIFileSharingEnabled`)은 선택이다.
- 서버 전송·업로드 코드는 추가하지 않는다.
- 기존 통계 JSON 공유는 그대로 둔다. 연구 모드는 별도 경로다.
- GOAL.md NFR-001에 "명시적 연구 모드 예외" 한 줄을 추가한다. 기본 정책은 바꾸지 않는다.

완료 기준:
- 시뮬레이터 합성 입력으로 저장한 `foa.wav`를 다시 읽어 `FOAAnalyzer.analyze`에 넣으면 실시간 결과와 동일하다(부동소수 ±1e-6).
- Release 빌드에서 동작한다. 합성 입력 플래그와 무관하다.
- 중지·백그라운드 시 파일이 닫히고 manifest가 완성된다. 비정상 종료의 부분 파일은 manifest 없음으로 식별된다.

### P0-3. 정답 데이터셋 수집 프로토콜 — EXP-023, REQ-NATIVE-029 / SC-52

측정은 사용자가 한다. 개발 담당은 절차 문서와 라벨 입력만 만든다.

- `docs_canonical/GROUND_TRUTH_PROTOCOL.md` 신설.
- 공통 조건: 삼각대 고정, 스피커 거리 1 m, 폰 세로, 카메라 정중앙에 스피커 마커, 스피커는 단일 출력 채널.
- **최소 세트(먼저)**: 방위 −90/−45/0/+45/+90°, 고도 0°, 백색잡음 10초, 각 2회 = 10세션. P0-4 축 검증은 이것만으로 한다.
- **전체 세트(나중)**: 위 5방위 × 고도 {0°, +30°} × 신호 {1 kHz 순음, 백색잡음, 음성 10초} × 3회 = 90세션. P1-5 판정에 쓴다.
- 앱 연구 모드에 "정답 방위·고도"와 "세션 라벨" 입력 필드를 둔다. manifest에 기록한다.
- 데이터는 저장소에 넣지 않는다. Git LFS 또는 외부 저장소에 두고, 저장소에는 `docs/reports/datasets/<id>.manifest.json`(SHA-256 포함)만 커밋한다.

완료 기준: 최소 세트 10세션의 manifest가 커밋된다.

### P0-4. FOA→카메라 축 검증 — EXP-024, REQ-NATIVE-030 / SC-53

README에 "축 대응 미검증"이라 적혀 있다. 열지도 신뢰의 전제이며, 최소 세트가 들어오면 즉시 처리한다.

- 0° 세션에서 대역 방향 벡터의 평균이 (0,0,+1)에서 몇 도 벗어나는지 계산한다.
- ±45°/±90° 세션에서 X 부호가 맞는지 확인한다.
- 결과를 `SpatialGeometry.swift`의 회전 행렬 상수 하나로 반영한다. 코드 곳곳의 축 가정을 이 상수 하나로 모은다.

완료 기준: 5방위 부호 일치 5/5, 평균 오차 수치 보고. 오차 15° 초과면 축 매핑만 재검토하고 알고리즘은 건드리지 않는다.

## 4. P1 — 데이터가 생기면 오프라인에서 반복한다

### P1-5. FOA 방향 추정 고도화 — REQ-NATIVE-031 / SC-54

현재 `FOAAnalysis.swift`는 3대역 고정, 대역당 `Re(W*·[X,Y,Z])` 합 하나로 방향을 낸다. 한 대역에 음원이 둘이면 벡터가 섞이고 반사에 취약하다(합성 반례 54° 오류).

순서(반드시 이 순서):
0. **기준선 먼저.** 현재 알고리즘을 P0-3 전체 세트에 돌려 방위 오차 중앙값·90분위·부호 오류율을 기록한다. 이 숫자 없이 알고리즘을 바꾸지 않는다.
1. bin별 의사강도(pseudo-intensity) 벡터를 계산해 **방향 히스토그램**을 만든다. 방위 5°, 고도 10° bin. 열지도는 히스토그램 피크에서 그린다.
2. 반사 억제: bin별 coherence gating + 최근 N윈도우 중앙값(시간 연속성).
3. 임계값(coherence 0.7, balance 0.65, ratio 0.25–1.8, spread 35°)을 `FOAThresholds` 구조체로 분리한다. 데이터셋으로 ROC를 그려 값을 정하고, 그때 `physicalAccuracyVerified`를 실제 값으로 바꾼다.
4. 대역 개수 변경은 데이터를 본 뒤 결정한다. 지금 늘리지 않는다.

완료 기준:
- 합성 반례(직접음 0°, 반사 90°, 1.4배)에서 히스토그램이 두 피크로 분리된다.
- 실측 전체 세트에서 기준선 대비 개선 수치를 보고한다.

### P1-6. FOA 합성 벤치마크 격자 — REQ-NATIVE-032 / SC-55

기존 `scripts/audit-foa-feasibility.mjs`를 격자 실행으로 확장한다. 새 스크립트를 만들지 않는다.

- 격자: SNR {∞, 20, 10, 0 dB} × 반사 {없음, 0.7배, 1.4배} × 방위 12 × seed 10.
- 출력: 방위 오차 분포, 보류율. `docs/reports/`에 JSON으로 남긴다.
- 이 수치는 실기기 예측이 아님을 문서에 명시한다. gate 임계로 쓰지 않는다.

### P1-7. Stereo 6단계 보정 경로 폐기 — REQ-NATIVE-033 / SC-56

`CaptureModel.swift` 983줄의 상당 부분이 Stereo 회전 보정(`DirectionCalibration`, `RotationCalibrationDiagnostics`, `AcousticBearing`의 stereo 부분)이다. 이 경로는 자체 반례(12 cm 이상 마이크의 ILD 약 0.9 dB < 임계 2 dB)로 이미 사장됐다.

- **P0-4 통과 후에만** 삭제한다. 그 전에는 건드리지 않는다.
- 삭제 범위는 보정 로직뿐이다. Stereo 파형 표시와 `stereoOutput` 수음은 유지한다.
- DEVLOG에 EXP 기록으로 보존한다.
- BUG-022(실패 문구 방법 편향)는 "경로 폐기로 해소"로 닫는다.
- BUG-023(새 세션 기록 소실)은 빌드 10의 5개 보관이 실기기에서 실제로 해결했는지 재현한 뒤 닫는다.
- 별도의 구조 리팩터는 하지 않는다. `CaptureModel`에 새 코드를 추가하지 않고, 신규 기능(연구 모드 등)은 새 타입에 둔다.

완료 기준: 삭제 커밋에서 기존 UI 테스트·Swift 테스트 전부 PASS. 줄 수 감소를 보고한다.

## 6. 선택 항목 (필수 아님, 근거가 생길 때만)

- **vDSP FFT 교체**: 먼저 `FOACaptureDiagnostics`에 윈도우당 처리 시간(ms)과 `ProcessInfo.thermalState`를 기록한다. 4채널 4096 윈도우(약 85 ms) 대비 처리 시간이 20 ms를 넘거나 thermal이 serious 이상이면 `vDSP`로 교체한다. 계측 없이 교체하지 않는다.
- **ESLint**: 새 코드에만 적용한다. 기존 파일 재포맷 금지. gate 필수 아님.
- **Playwright WebKit**: 렌더링·넘침 스모크 1개만. 오디오 E2E는 실기기로 대체한다.

## 8. 판정 기준 (Go / No-Go)

P0-3 전체 세트 기준으로 P1-5 완료 시점에 판정한다.

- 방위 오차 중앙값 ≤15°, 부호 오류 ≤5% → FOA 경로 계속. AR 자세 융합을 열지도에 재연결한다.
- 15~30° → P1-5의 반사 억제를 1회 더 반복한 뒤 재판정.
- >30° 또는 부호가 무작위 → Apple FOA 인코더의 방향 정보가 부족한 것으로 본다. 문서에 이미 적힌 외부 마이크 배열(공통 클록·알려진 기하·채널별 원음) 경로로 전환한다. 이때 기존 `packages/localization`의 GCC-PHAT 경로를 그대로 쓴다.

이 숫자는 지금 정해 두는 값이다. 데이터를 본 뒤에 기준을 옮기지 않는다.

## 10. 금지 사항 (재확인)

- 실패를 문서화로 끝내지 않는다. 다음 측정으로 확정할 수 있는 형태로만 기록한다.
