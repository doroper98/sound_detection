# 연구 녹음과 방향 확인 절차

REQ-NATIVE-031~034, REQ-ENGINE-002 / SC-53~57. 정답 각도는 기록·채점에만 사용한다. 열지도를 만드는 입력에 넣지 않는다.

## 먼저 파일 한 개 보내기

1. 앱 **측정 상세 → 원음과 폰 자세 저장**을 켠다. 기본값은 꺼짐이다.
2. 세션 이름을 적고, 실제 소리 위치·높이·재생 소리를 고른다.
3. 상세를 닫고 **후면 카메라·수음 시작**을 누른다. 빨간 **REC**가 보여야 녹음 중이다.
4. 10초 정도 측정하고 **계측 중지**를 누른다.
5. **측정 상세 → 연구 데이터 공유 · 최신 ZIP**을 누른다. ZIP 하나를 현재 대화에 첨부한다. 직접 PC에 옮기거나 명령어를 실행할 필요는 없다. 공유 대상 앱에서 첨부를 바로 받을 수 없으면 공유 시트의 ‘파일에 저장’ 후 해당 ZIP을 첨부한다.

지금 있는 TV/스피커를 그대로 사용한 파일은 저장·재분석 확인용으로 먼저 보낼 수 있다. 아래의 위치·거리 조건을 맞추지 않은 파일을 정답 데이터셋에 포함하지 않는다. 새 IPA 설치 후 연구 녹음을 켜기 전까지는 기존처럼 통계만 저장된다.

## 최소 방향 확인: 10개

- 폰은 **세로로 삼각대에 고정**한다. 10개를 찍는 동안 폰의 위치와 방향을 유지한다.
- 소리 나는 스피커는 **하나**만 쓴다. PC 좌우 스피커를 동시에 울리지 않는다. 백색잡음을 계속 재생한다.
- 폰이 바라보는 정면에 0° 기준 표시를 둔다. 처음에는 스피커를 그 표시에 놓고 카메라 중앙에 맞춘다.
- 스피커를 폰에서 **1m**, 폰과 같은 높이에 놓는다. 좌우 측정에서는 그 거리의 원을 따라 스피커 위치만 옮긴다. 폰을 돌려 따라가지 않는다.
- 아래 각 위치에서 **10초 녹음 → 중지**를 2번 한다. 옮기는 동안 녹음하지 않는다. ±90° 스피커는 화면 밖에 있을 수 있다.

| 카메라 화면 기준 소리 위치 | 앱 소리 위치 | 높이 | 이름 예시 | 횟수 |
|---|---|---|---|---|
| 완전히 왼쪽 | −90° | 0° | 방1-왼쪽90 | 1, 2 |
| 왼쪽 대각선 | −45° | 0° | 방1-왼쪽45 | 1, 2 |
| 정면 | 0° | 0° | 방1-정면 | 1, 2 |
| 오른쪽 대각선 | +45° | 0° | 방1-오른쪽45 | 1, 2 |
| 완전히 오른쪽 | +90° | 0° | 방1-오른쪽90 | 1, 2 |

이 10개로 먼저 정면 방향 오차와 좌우 부호를 확인한다. 평균 오차 15°를 넘으면 축 대응을 먼저 검토하며 추정 알고리즘을 바꾸지 않는다. 좌우 부호 5/5에는 정면의 좌우 오차도 수치로 따로 보고한다. 이 최소 세트만으로 일반 환경의 정확도를 검증했다고 선언하지 않는다.

## 전체 기준선: 나중에 90개

최소 세트와 축 확인 이후에 진행한다. 방위 5개 × 높이 2개(0°, 위 30°) × 소리 3개(1kHz 순음, 백색잡음, 음성) × 각 3회 = 90개, 각 10초다. 방·스피커·거리·음량 설정을 같게 유지한다. 소리 내용, 주변 소음, 벽과의 거리, 위치 측정 오차를 함께 적는다.

기존 엔진으로 방위 오차 중앙값·90분위·부호 오류율·보류율을 먼저 계산한다. 보류된 구간을 제외한 오차만으로 성능을 과장하지 않도록 전체/채택 수와 세션별 값을 함께 보고한다. 알고리즘 변경 후에는 같은 데이터와 별도 검증 세트를 비교한다.

## 파일과 보관 위치

아이폰 앱 Documents/ResearchSessions/세션UUID 안에 아래 파일을 만든다. 기본 모드에는 원음 파일이 생기지 않는다. 녹음·정답 라벨·AR 상대 좌표가 들어가며 사진·영상·장치 고유 ID는 들어가지 않는다. 세션당 원음은 최대 120초, 48kHz FOA만 기준 10초 약 7.7MB이며 선택 스테레오는 약 3.8MB를 더 쓴다.

| 파일 | 내용 |
|---|---|
| foa.wav | 4채널 Float32, ACN/SN3D W,Y,Z,X 원래 순서 |
| pose.jsonl | AR 프레임 host 시각, quaternion x/y/z/w, 상대 위치, 카메라 축, tracking 상태 |
| audio-timeline.jsonl | 각 원본 버퍼의 첫 샘플 시각과 WAV 프레임 구간. 누락 구간을 복원하는 기준 |
| analysis.jsonl | 실시간 엔진이 실제 분석한 구간 중간 시각·길이·FOAAnalysis |
| manifest.json | 완료 표시, UTC 시각·첫 오디오 host 시각, 빌드·기기 모델·형식·라벨·정답 각도·파일 SHA-256 |
| stereo.wav | 옵션을 켰을 때의 별도 2채널 참고 신호 |

여기서 원음은 **iOS가 제공한 FOA PCM을 그대로 저장한 것**이다. 물리 마이크별 가공 전 신호라고 가정하지 않는다. 카메라 축·물리 마이크·하드웨어 동기화 검증도 별개다.

파일을 모두 닫고 해시를 계산한 뒤에만 manifest를 완성한다. 앱 강제 종료·디스크 오류·대기 한도 초과 등으로 manifest가 없으면 **미완료 데이터**이며 정상 세션으로 채점하지 않는다. 백그라운드에서 주어진 마감 시간을 넘겨도 미완료로 남긴다. 화면은 저장 완료/미완료를 구분한다.

원음과 ZIP은 Git에 넣지 않는다. 사용자가 공유한 데이터는 접근 가능한 외부 보관 위치에 두고, 검증된 세션의 manifest만 docs/reports/datasets/&lt;id&gt;.manifest.json에 등록한다. 현재 실제 최소 세트 10개와 전체 90개는 확보 전이다.

## 개발자 재분석

ZIP을 세션 폴더 하나로 푼 후 `foa-replay <폴더> --output <결과.json>`을 실행한다. 도구는 같은 Swift PCMWindowAssembler → FOAAnalyzer를 사용한다. 파일 크기/해시/채널/시각을 먼저 검사하고 실제 기록된 실시간 구간과 ±1e-6로 비교한다. 원음이 보존되어 실시간 전달 제한으로 화면에 도착하지 않은 구간도 재분석할 수 있다.

poseAlignment는 기록된 AR 프레임을 같은 대응 검사에 넣은 **오프라인 재대응**이다. 가상 처리 시각은 윈도우 종료+60ms이며 실시간 UI 스케줄링 지연을 재연한 결과가 아니다. 실시간 FOAAnalysis 일치와 카메라 전달 시점 재현을 혼동하지 않는다. 소스 위치 라벨을 바꿔도 추론은 같아야 한다.
