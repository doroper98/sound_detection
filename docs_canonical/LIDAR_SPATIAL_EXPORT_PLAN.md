# 라이다 공간 지도와 소리 분석 내보내기 — 후속 계획

기록일: 2026-09-23. REQ-NATIVE-018 / SC-39. **상태: DEFERRED — 기본 기능 검증 후 검토. 구현 완료 아님.**

사용자 요청: 라이다로 관측 가능한 공간을 그려 카메라 영상에 공간 정보를 더하고, 소리 위치 식별에 활용하며 결과를 내보내고 싶다. 지금은 스테레오 수음·위치 추정·열지도·영역 안 주파수 표시의 정확한 구현을 우선한다.

## 가능한 구성과 현재 상태

- 현재 빌드 7은 후면 AR 카메라의 자세·상대 위치를 사용한다. `SpatialCamera.swift`는 `sceneReconstruction`이나 `sceneDepth`를 요청하지 않으며 공간 mesh를 수집·저장·내보내지 않는다.
- 후속으로 기기 지원 여부를 검사한 뒤 ARKit의 scene reconstruction과 depth/confidence 정보를 사용할 수 있다. 관측한 표면을 카메라와 같은 좌표계에 놓고, 깊이·벽/바닥 등의 분류·아직 관측하지 못한 영역을 표시한다. ARKit은 LiDAR 깊이에서 mesh를 만들며 표면 위치 추정과 가림 표현에 활용한다. [Apple scene reconstruction](https://developer.apple.com/documentation/arkit/visualizing-and-interacting-with-a-reconstructed-scene)
- 카메라 영상과 깊이 자료를 결합한 점군 표현도 가능하다. 관측 범위는 지원 기기와 표면·가림·신뢰도·실제 유효 깊이로 정하고, 보지 못한 부분을 완성된 공간처럼 채우지 않는다. 이 계획에서 최대 거리나 정밀도 수치를 보장하지 않는다. [Apple scene depth](https://developer.apple.com/documentation/arkit/displaying-a-point-cloud-using-scene-depth)
- 공간 위에 소리 위치 **후보와 추정 범위**, 수신 dBFS, 대표 주파수/대역을 겹친다. 현재의 단일 고정 음원 가정을 유지하며 다중 음원 분리는 별도 과제다.

## 음향 정확도에 대한 검증 가설

공간의 구조를 알면 소리 후보를 현실 좌표에 안정적으로 표시하고, 가림·반사 가능성이나 표면과의 관계를 검토하는 데 도움이 될 수 있다. 이는 개발 가설이며 Apple의 공간 재구성 기능 자체가 음원 위치 정확도를 보장한다는 뜻은 아니다.

라이다는 빛으로 표면까지의 거리를 얻는다. 그 표면이 실제 소리 발생 위치인지, 소리가 벽 뒤나 공중에서 왔는지, 반사음인지 알려주지 않는다. 가까운 표면과 음향 방향의 교차점을 곧바로 정답으로 확정하지 않는다. 재질별 흡음·반사 계수도 mesh 분류만으로 확정할 수 없다. 기존의 마이크 처리·보정 오차·두 채널 기하 모호성은 따로 검증한다.

같은 관측 자료에서 공간 정보 사용 전/후의 방향·거리 오차, 오탐률, 후보 미표시율을 비교한다. 개선이 확인된 조건만 적용하고 정확도가 악화되는 경우 기존 음향 후보를 유지하거나 미확정으로 표시한다. 근거리 공간 스캔을 기존 500m 드론 목표 달성으로 해석하지 않는다.

## 내보내기 초안

| 구성 | 제안 내용 |
|---|---|
| 공간 | 관측 mesh/점군, 분류·품질, 누락 영역. PLY/OBJ 등의 형식과 단위 명시를 검토 |
| 소리 | JSON/CSV의 시각, 주파수·대역, 수신 dBFS, 후보 위치와 계산상 범위, 보정·추적 상태 |
| 좌표계 | 세션 원점·축·미터 단위, 카메라/mesh/audio 변환과 시각 기준, 세션 재시작 경계 |
| 보기용 결과 | 카메라 위 열지도 캡처 또는 공간 뷰. 영상·텍스처 포함 여부를 내보내기 때 선택 |
| 재현 자료 | 앱·알고리즘 버전, 설정, 검증 상태. 좌표만 떼어 내지 않고 해석에 필요한 메타데이터 동봉 |

위 형식은 제안이며 현재 앱의 내보내기 기능이 아니다. RoomPlan의 실내 구조 모델은 USD/USDZ 출력 경로가 있으나 ARKit 원시 mesh와 동일하지 않다. 실내 도면이 필요한 단계에서 별도 선택한다. [Apple RoomPlan export](https://developer.apple.com/documentation/roomplan/capturedroom/export(to:exportoptions:))

공간·영상 저장은 사용자가 기능을 시작하고 포함 항목을 선택하는 흐름으로 설계한다. 현 단계에서 기존 앱의 통계만 공유하는 동작은 변경하지 않는다. 공간 정보가 없는 좌표를 GPS/절대 지리 좌표처럼 표시하지 않는다.

## 다시 꺼낼 시점

먼저 [기본 기능 실기기 검증](NATIVE_FIELD_VALIDATION.md)의 안정성, 보정 반복성, 알려진 위치의 오차, 열지도·주파수 일치, 잘못된 표시 억제에 대한 결과를 확보하고 기본 검증 완료 여부를 기록한다. 합성 테스트나 IPA 빌드 성공만으로 이 조건을 충족했다고 보지 않는다.

기본 기능 검증 완료가 기록되거나 사용자가 다음 단계로 전환한다고 하면 이 계획을 한 번 리마인드한다. 이 작업에 매일 오전 10시(Asia/Seoul) 진행 상태를 확인하는 리마인드를 등록했다. 변화가 없으면 정기 상태 보고를 보내지 않는다. 리마인드는 계획 검토를 위한 것이며 구현 자동 시작을 뜻하지 않는다.

SC-39 문서 완료 조건: 요청·우선순위·가능성과 한계·내보내기 초안·재검토 조건이 보존되고 실제 리마인드가 등록되어 있을 것. 기능 구현 성공 기준은 기본 검증 후 별도로 정의한다.
