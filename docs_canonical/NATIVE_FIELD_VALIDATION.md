# 기본 기능 실기기 검증 순서

2026-09-23 · REQ-NATIVE-019 / SC-40 · **절차 준비 완료, 실기기 검증 대기.**

목표는 화면이 움직이는 것과 실제 소리 방향·위치가 맞는 것을 구분하고, 틀린 위치를 자신 있게 표시하는 경우부터 찾아 수정하는 것이다. 사용자가 설치 가능한 때 빌드 7 이상으로 진행한다. 외부에 있는 동안 즉시 설치나 측정을 요구하지 않는다.

## 기준 상태

### 빌드 10 실측 확보 및 빌드 11 확인 항목 (2026-09-24)

사용자 JSON에서 FOA 4채널/48 kHz/ACN·SN3D와 별도 Stereo, 카메라 병행 연결 1,189구간이 확인됐다. 반짝이는 표시의 소프트웨어 원인은 단일 구간 통과/거부 즉시 전환이며, 마지막 구간은 에너지 비율 등의 기준으로 거부됐다. 실제 큰 비율의 물리 원인은 아직 확정하지 못했다. [실측 선택 필드와 판단 범위](../docs/reports/2026-09-24-iphone17pro-build10-flicker-analysis.json).

빌드 11은 시작 방법이 같으며 복잡한 재보정을 요구하지 않는다. 중앙 카메라 영역을 비우고 주파수·dBFS는 글씨만 표시한다. 자세한 수치, 파형 FPS, 입력 선택, 범례는 측정 상세에 있다. 카메라 계측 중 자동 잠금을 방지하고 중지/앱 전환에서는 기존 설정으로 돌아간다. 표시 후보는 3회 연속 확인하며 짧은 재확인은 흐린 “직전 관측”으로 구분한다. 조용해지거나 추적에 실패하면 즉시 지운다.

새 JSON의 `foa.timeline.history`는 최근 240개 처리 구간의 `timestampUTC`/`elapsedSeconds`/음향 및 자세 판정/대역별 `failedChecks`를 포함한다. 구간 중간 시각이며 화면 표시 시각·전체 세션 원본 기록은 아니다. 이전 구간은 `omittedEarlierEntries`와 전체 누계로 구분한다. UTC(Z)는 한국 시각에서 9시간을 뺀 값이다. `exportedAt`과 측정 시작/종료는 별개다. 같은 측정을 다시 공유해도 고유 파일명이 생성된다. 과거 빌드의 기록에 없던 구간 시각을 소급해서 만들어 넣지는 않는다.

빌드 10은 후면 카메라에서 **공간 오디오 시작 → 방향 열지도 확인**으로 진행한다. 아래 빌드 7~9의 6단계 보정은 새 FOA 경로에 적용하지 않는다. 우선 실제 FOA 4채널/ACN·SN3D, 별도 Stereo 2채널, 카메라 연결 수, 한 고정 음원의 화면 좌우·위아래 이동과 표시 부호를 확인한다. 기본 FOA→세로 카메라 축 대응은 가정이며 실측 전이다. 거리값은 표시하지 않는다. 빌드 10부터 최근 진단 5개를 별도 보관하므로 측정 상세의 **이전 진단**에서도 실패 세션을 공유할 수 있다. 카메라/수음 실패, 무음, 반사에서의 보류/오표시도 함께 남긴다.

### 빌드 10에서 사용자가 할 일

1. Sideloadly로 빌드 10 IPA를 기존 앱 위에 설치한다. 앱을 삭제하면 보관한 진단도 사라질 수 있다.
2. 앱을 열어 폰을 세로로 잡고 후면 카메라 화면의 **카메라·수음 시작**을 누른다. 기존 1/6 보정이나 입력 비교는 하지 않는다.
3. 한 스피커에서 소리를 내고 카메라에 스피커가 보이도록 잠시 멈춘다. 화면의 열섬·주파수와 실제 스피커 방향이 맞는지 확인한다. 보류/오류가 나면 측정 상세에서 진단 JSON을 공유한다. 새 수음을 시작한 뒤라면 **이전 진단**을 펼쳐 해당 시간을 고른다.

첫 확인에는 복잡한 스피커 배치나 각도 측정을 요구하지 않는다. 실제 포맷과 카메라 대응을 먼저 확인하고, 그 결과가 맞으면 독립 기준각으로 정확도를 평가한다. 열섬 크기는 기하학적 음원 크기가 아니며 색은 수신 디지털 레벨(dBFS)이다. FOA 경로의 좌우/상하 축은 확인 전 가정이고 거리·공간 음압·물리 마이크 4개 독립 수음을 주장하지 않는다.

2026-09-23 추가: 최신 build9 JSON은 audioDetails로 시작한 별도 audio-only 세션이다. 실패한 회전 보정의 `diagnostics.steps`/`responses`가 없다. **실패 직후 측정 상세에서 새 수음을 시작하지 말고 JSON을 공유**해야 한다. 보고서는 새 수음 시작 때 초기화된다. 원인 판정과 다음 계측 기준은 [가능성 재진단](NATIVE_LOCALIZATION_FEASIBILITY.md)을 먼저 적용한다. 아래 절차를 재시도만 하는 방식으로 사용하지 않는다.

빌드 7 코드 `13864bd`의 Swift 59개·합성 iOS UI 23개·Release 빌드는 통과했다. 빌드 3/4의 실측은 후면 카메라와 스테레오 입력 활성의 근거다. 빌드 7의 AR와 스테레오 동시 사용, 보정 재현성, 음향 위치 정확도는 아직 실기기 증거가 없다. 세부 근거는 [TESTING.md](TESTING.md)에 보존한다.

## 빌드 7~9의 기존 보정·측정 순서 (보존 기록)

| 순서 | 조건과 동작 | 확인·기록할 항목 |
|---|---|---|
| 1. 수음 안정성 | 같은 방에서 한 스피커만 사용, 카메라와 수음 60초. 중지/재시작 3회 및 잠금 복귀 | 실제 2채널·샘플률·양쪽 활성, 누락/route 이벤트, 카메라 유지, 파형의 실제 갱신 속도. 중지/잠금 뒤 현재 표시 제거 |
| 2. 보정 반복성 | 고정된 광대역 음원을 정면·비슷한 높이·1m 이상에 두고 앱의 회전 보정 6단계를 수행. 같은 조건에서 독립적으로 3회 | 보정 성공/실패 모두 보존. 실패 이유, 소요 시간, 반복 측정 응답과 각도 오차. 중앙 맞춤에 사용한 관측은 독립 정확도 평가로 세지 않음 |
| 3. 방향 평가 | 보정에 쓰지 않은 정면 및 좌우 약 10°/20°의 알려진 방향에서, 같은 고정 음원을 5초씩 관측. 각 3회 | 표시 유무, 좌우 부호, 기준각 대비 오차, 흔들림, 유효 비율. 알려진 방향은 줄자·배치 측정 등 별도 기준으로 구하고 앱 추정값을 정답으로 쓰지 않음 |
| 4. 공간 후보 | 같은 고정 음원에 대해 서로 다른 위치·높이·자세에서 천천히 관측하고 구간마다 정지. 독립 이동 간격 합이 30cm 이상인 조건과 제자리/수평만인 조건을 분리 | 거리·높이의 기준값과 오차, 후보 표시까지 시간, 미표시 비율. 퇴화한 관측에서 거리/높이를 억지로 확정하지 않는지 확인 |

| 6. 잘못된 표시 억제 | 음원 끄기, 가려진/추적 불량 영상, 범위를 벗어난 회전, 배경 전환, 다른 소리 또는 두 스피커 조건을 별도 측정 | 오래된 열섬/주파수가 현재값처럼 남는지, 잘못된 점을 새로 내는지, 후보를 거부한 이유. 두 음원이 생겼다고 항상 자동 식별된다고 가정하지 않음 |

광대역 한 음원 검증에는 기존 제공한 `소리-보정용-테스트.html`의 도움말을 따른다. 좌우 스피커가 동시에 다른 소리를 내는 영상은 초기 단일 음원 정확도 기준으로 쓰지 않는다. 앱/PC 볼륨 숫자를 교정된 dB SPL이나 정확한 dB 변화량으로 간주하지 않는다.

## 기록과 판단

### 세로·가로 비교 (다음 구현·검증 항목)

2026-09-23 사용자가 가로 수음의 타당성을 제안했다. Apple의 `inputOrientation`은 내장 스테레오의 좌우 기준을 정의하고 영상 방향에 맞춰 설정하며, 기록 중 변경하지 않도록 안내한다. 세로 스테레오도 지원되므로 이번 보정 거부를 세로 자세 탓이라고 확정하지 않는다. [Apple 입력 방향](https://developer.apple.com/documentation/avfaudio/avaudiosession/inputorientation)

현재 빌드 7/8은 마이크 `.portrait`, AR view/projection `.portrait`, UI 세로 고정이다. 폰만 가로로 눕혀 비교하면 동일 조건의 가로 입력 시험이 아니다. 가로를 지원할 때 UI·마이크 요청/실제 방향·카메라 투영·AR 축을 함께 맞추고, 세션 시작 때 고정하며 모드 변경 시 기존 보정을 초기화해야 한다. 그 구현 뒤 같은 기기/방/음원/거리/각도에서 세로·가로를 각각 보정하여 좌우 응답 기울기·반복 오차·유효 지연률·실제 방향 오차를 비교한다. 검증 전 가로가 더 정확하다고 단정하지 않는다.

각 실행의 버전, 방/배치, 음원 종류, 독립 측정한 기준 방향·거리·높이와 기준 측정의 오차, 보정 조건, 측정 중 표시 및 중지 후 JSON을 같은 실행 ID로 묶는다. 현재 JSON은 전체 영상·소리·모든 위치 시계열을 보존하지 않으므로 결과에 없는 시점의 정확도나 지연을 복원했다고 주장하지 않는다. 필요한 경우 사용자 관측 기록을 별도로 남기고, 추가 통계 계측이 필요한 부분부터 구현한다.

평가표에는 방향/거리 오차의 중앙값·최대값, 반복 수, 성공·미표시·오탐 수를 함께 적는다. 작은 표본에서 백분위수나 신뢰수준을 과장하지 않는다. 표시된 사례만 뽑아 정확도를 계산하지 않는다. 관측 조건과 유효 범위가 다른 결과를 하나로 섞지 않는다.

SC-40의 이번 완료 범위는 재현 가능한 절차와 증거 항목의 준비다. 실기기 통과 조건·허용 오차는 목표 사용 범위와 기준 측정 오차를 정한 뒤 평가 전에 명시한다. 데이터가 없는 현재 상태는 **미검증**이다. 문제가 나오면 수음/시각 정렬 → 보정과 좌표 → 오탐 억제 → 표시 순으로 수정하고 같은 조건에서 재측정한다.

기본 검증 완료 판정이 기록된 뒤 [라이다 후속 계획](LIDAR_SPATIAL_EXPORT_PLAN.md)을 검토한다. 완료 선언 없이 테스트 개수만 늘어난 상태를 다음 단계의 근거로 삼지 않는다.
