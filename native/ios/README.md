# iPhone 네이티브 스테레오 진단

## 현재 작업: 빌드 12 연구 녹음과 ZIP 공유

기본값은 원음 저장 OFF다. **측정 상세 → 원음과 폰 자세 저장**을 켜고 후면 카메라·수음을 시작하면 빨간 REC와 함께 FOA 원음·AR 자세·버퍼 시각·실시간 분석을 아이폰 Documents에 저장한다. 중지 후 **연구 데이터 공유**로 ZIP 하나를 이 대화에 첨부한다. 자동 업로드와 카메라 영상 저장은 없다. 앱 재시작 시 연구 녹음은 다시 OFF다.

같은 Swift 엔진의 `foa-replay <세션 폴더> --output <결과.json>`으로 반복 분석한다. 파일 SHA-256·PCM 형식·시각을 검사하며 실시간과 재생 결과를 비교한다. 앱 녹음·중지·백그라운드·ZIP의 검증이 통과하기 전에는 IPA를 전달하지 않는다. 실제 정답 데이터 확보 전까지 방향 추정 기준은 유지한다.

[쉬운 녹음/공유와 정답 10세션 절차](../../docs_canonical/GROUND_TRUTH_PROTOCOL.md) · [외부 검토 반영 범위](../../docs/reviews/2026-09-24-review-disposition.md). 아래 빌드 2~8 설명은 당시 기능 이력이다. 원음 저장 없음이라는 과거 정책은 현재도 기본 모드에 적용되며, 명시적 연구 녹음만 예외다.

## 빌드 8 보정 실패 진단·쉬운 회전 안내

큰 화살표는 폰이 바라볼 방향이다. 폰을 오른쪽으로 돌리면 화면 속 스피커 각도는 음수가 된다. 화면 중앙 + 정렬은 시작할 때 한 번이며 회전 중 계속 중앙에 붙들어 두지 않는다. 각 자세에서 다음 단계로 넘어갈 때까지 멈춘다.

schemaVersion 8의 `spatial.calibration.diagnostics`에 6단계의 각도/입력 dBFS/좌우 차이/변동/시간차 가용률/대역 요약, 각 추정 방법의 실패 조건과 검사 기준이 남는다. 실패 원인은 재현된 실제 판정 조건이며 방의 반사나 사용자 움직임 같은 물리 원인을 확정한 것이 아니다. 기존 임계값은 바꾸지 않는다. 정상 정지/JSON 공유 뒤 거부 결과가 남고, 새 수음/보정을 시작하면 초기화한다. 빌드 7의 빠진 과거 통계를 복구하지는 못한다.

빌드 7의 사용자 실측은 6단계·150개 측정 후 거부였다. 카메라/스테레오 시작과 양쪽 3435개 활성 구간을 확인했지만 보정/위치 정확도 성공은 아니다. 이번 빌드는 원인 진단과 안내를 보완하며 정확도 검증은 계속 진행한다.

## 빌드 7 열지도·영역 주파수

빌드 6의 방향/위치 토대에 요청된 열지도와 작은 주파수 표시를 연결한다. 아래의 시작·회전 보정·이동 관측 순서는 동일하다. 방향만 유효하면 세로 열지도, 위치 후보가 있으면 주변을 부드러운 열섬으로 강조한다. 열섬 안에는 현재 입력의 대표 Hz/kHz와 dBFS를 작게 표시하고, 뚜렷한 peak가 없는 광대역 소리는 에너지 10~90% 주파수 구간을 표시한다.

색상은 폰에서 받은 입력의 고정 −65~−15 dBFS 척도다. 실제 공간 음압/SPL 지도, 물체 크기, 확률 신뢰구간이 아니다. 한 소리의 입력 전체 통계이며 여러 음원을 분리하지 않는다. 입력 무효/오래된 자료/중지/배경 때 현재 열지도와 주파수는 사라진다. schemaVersion 7의 최신 프레임에는 `soundSpectrum`, 공간 보고에는 `sound`와 해석 문구가 추가된다. 원음은 저장하지 않는다.

## 빌드 6 소리 방향·공간 후보 (이전 단계)

빌드 5 설치/검사는 생략해도 된다. 빌드 6은 기존 스테레오·최대 60fps 파형에 AR 카메라, 앱 안 회전 보정, 실시간 방향 띠, 여러 위치에서의 조건부 공간 후보를 연결한다. 후면 카메라 전용이며 정확도는 실기기 미검증이다.

1. 후면 **카메라·수음 시작**. AR 추적 준비를 위해 밝고 무늬가 있는 주변을 비춘다.
2. 한 스피커에서 일정한 광대역 소리를 내고 1m 이상 거리, 비슷한 높이를 유지한다. **소리 찾기 → 카메라로 중앙 정렬**을 누르고 실제 카메라 중앙 +에 스피커를 맞춘 뒤 **정렬 완료 · 보정 시작**을 누른다.
3. 폰의 위치는 고정하고 좌우로만 회전한다. 소리 각도 0/−25/+25°에 맞춰 약 2.5초 멈추는 과정을 두 번 진행한다. 실제 AR 자세·신호 통계로 응답을 맞추며 이동/소리 불일치/재현성 부족이면 보류한다.
4. 성공하면 카메라 위 초록 띠가 수평 방향 범위를 표시한다. 소리를 고정해 둔 채 폰을 옆으로 30~80cm 옮기고 잠시 멈추며 관측한다. 높이를 구분하려면 조금 기울인 자세에서도 반복한다. 독립 관측·기하·잔차 조건이 충족되면 원과 대략적인 거리가 나타난다.
5. 소리/장소가 바뀌면 재보정, 같은 소리의 관측만 다시 모으려면 **위치 관측 초기화**. 새 수음은 보정도 초기화한다. **상세 → 진단 JSON 공유**로 마지막 통계와 상대 좌표/추정 결과를 보존한다.

띠는 높이·거리를 정하지 않는다. 원은 조건부 실험 후보이며 표시 반경은 모델의 계산상 민감도다. 검증된 신뢰구간이나 cm 정확도가 아니다. 고정된 한 소리·동일 스펙트럼/환경·전방·보정 각도 안이라는 조건이 있으며 후방 구별/동시에 여러 소리/이동 음원 추적을 주장하지 않는다. 입력이 약하거나 모호하면 예전 점을 계속 표시하지 않는다.

후면 AR 세션은 오디오 캡처를 끄고 기존 AVAudioEngine만 PCM을 받는다. 원음·영상·AR 월드맵을 저장하지 않는다. schemaVersion 6의 공유 JSON에는 음향 통계, 보정 계수, 세션 내 상대 기기 좌표와 시간표시가 있는 마지막 추정이 포함된다. 실제 GPS 위치가 아니다. 물리 마이크/하드웨어 동기화/음향 정확도 검증 플래그는 계속 false다. `localizationEnabled`는 경험적 추정 기능 활성 여부이며 정확도 인증이 아니다.

아래 빌드 1~5 절은 당시 동작 기록이다. 현재 업데이트에는 빌드 8 IPA를 사용한다.

## 빌드 5: 방향 비교·부드러운 파형

- 카메라 화면의 파형을 계산에서 분리해 최대 60fps로 표시한다. 실제 PCM의 10ms 창을 순차 표시하며 기본 약 120ms 지연이 있다. 카메라 화면에는 최근 표시 속도, 상세에는 마지막 표시 속도를 보여주고 JSON의 waveformDisplay에는 측정 시각도 기록한다. 상세/방향 비교 화면에서는 가려진 파형 그리기를 중지하고 복귀 시 재개한다. 수음·분석은 계속된다. 기기·전력 상태에 따라 낮아질 수 있다.
- 후면으로 카메라·수음을 시작한 뒤 상단 **방향 비교**를 누른다. 폰을 세로로 고정하고 후면 카메라가 보는 쪽에 한 소리원만 두며 화면 기준 왼쪽·정면·오른쪽으로 옮긴다. 약 1m의 비슷한 거리에서 종이 비비기처럼 주파수가 다양한 소리를 각 위치에서 계속 낸다. 버튼 → 3초 준비 → 5초 수집, 같은 순서 두 번이다. 폰을 돌리지 않는다.
- 여섯 구간 뒤 **비교 JSON 공유**. 중단된 구간·시간차 보류 상태도 통계에 남는다. 같은 세션 안의 누적 통계이며 앱 종료/새 수음/초기화 전 공유해야 보존된다. 원음·파형·영상은 파일로 저장하지 않는다.
- 품질 부족·폰 움직임·반복 불일치는 이유를 표시한다. 위치별 시간차가 반복해서 구분돼도 아직 각도·거리·3D 위치 계산이나 물리 음향 교정 완료가 아니다.

웹에서 받은 PCM은 iPhone 17 Pro의 Chrome/Safari 모두 두 칸 중 한 칸만 활성 신호였다. 이 앱은 AVAudioSession의 **내장 stereo polar pattern**을 선택하고 AVAudioEngine에서 실제 PCM을 직접 받는다. WKWebView로 웹사이트를 감싸는 방식이 아니다.

현재는 입력·채널 간 신호 지연을 검증하는 개발용 앱이다. 웹 제품 버전은 0.4.0을 유지한다. App Store/TestFlight 배포나 아이폰 실측 성공을 의미하지 않는다.

## 빌드 4: 작은 좌우 입력 파형

카메라 화면 하단에서 L(초록)/R(청록) 파형을 따로 볼 수 있다. 두 그래프는 같은 최근 최대 10ms를 공통 자동 배율로 표시하며, 절대 음량은 기존 dBFS로 읽는다. 수음 중지/백그라운드/재시작 또는 350ms 이상 새 입력이 없으면 파형을 지운다. 화면 표시용 자료만 메모리에 두며 JSON·녹음 파일에는 포함하지 않는다.

현재 설치 사용자는 **SoundFieldStereo-build4-unsigned.ipa**를 Sideloadly에 새로 선택해 덮어쓰고 앱 하단 **빌드 4**를 확인한다. 빌드 3의 사용자 실측에서 48kHz 실제 2채널·245개 좌우 활성 구간이 확인됐으며, 파형 추가 후 실제 기기 동작은 별도 확인한다. [빌드 3 실측 해석](../../docs/reports/2026-09-22-iphone17pro-native-build3-analysis.json).

## 빌드 3: 실기기 override 알림 수정

사용자 빌드 2 JSON은 후면 Stereo·세션/하드웨어/tap 2채널·48kHz까지 설정한 뒤 첫 분석 전 `routeUnknown(4)`로 중지했다. 실제 원인은 출력 override 알림을 누락한 처리이며, `routeMatches=false`도 이 알림에서는 실제 검사한 결과가 아니었다. 빌드 3은 해당 알림에서도 입력 조건을 직접 검사해 동일한 스테레오 경로는 유지하고 실제 변경은 거부한다. [Apple override 설명](https://developer.apple.com/documentation/avfaudio/avaudiosession/routechangereason/override).

전달받은 **SoundFieldStereo-build3-unsigned.ipa**를 기존 Sideloadly에 새로 선택하고 같은 Apple 계정·번들 설정으로 덮어쓴다. Done 후 앱 하단 **빌드 3**을 확인하고 기본 화면 **카메라·수음 시작**으로 검사한다. 오류가 나면 다시 시작하기 전에 **측정 상세 → 진단 JSON 공유**로 해당 기록을 보존한다. 새 보고서는 입력 검사 세부 항목과 시작 버튼 경로를 포함한다. 카메라 시작 직후 중지했다는 사용자 설명과 기존 JSON의 카메라 false 값 사이 차이는 미확정이다.

코드 `ac5562d`의 [Mac CI](https://github.com/doroper98/sound_detection/actions/runs/35730115675)에서 Swift 27/27·합성 UI 13/13·Release 기기 빌드와 IPA 포장 PASS. [영구 결과](../../docs/reports/2026-09-22-native-override-verification.json)에 파일 해시와 실기기 미검증 범위를 기록했다.

## 빌드 2: 전체 화면 카메라와 시작 알림 수정

앱을 열면 전체 화면 카메라 영역과 하단 조작부가 나타난다. **카메라·수음 시작**을 눌러 카메라·마이크 권한을 차례로 허용한다. 전면/후면은 시작 전에 선택하며 영상은 화면 미리보기만 제공한다. 원음·영상 파일 저장, 서버 전송, 실제 음원 위치 오버레이는 없다. **측정 상세**에서 기존 채널 검사·관측 기록·JSON 공유를 사용할 수 있다. 하단의 **빌드 2**로 교체 여부를 확인한다.

영상 세션은 마이크 입력을 추가하거나 AVAudioSession을 자동 변경하지 않는다. 중지·백그라운드·카메라 인터럽트 시 입력을 해제한다. 수음 시작 직후 정상 설정 알림을 무조건 중지하던 처리를 변경했으며 실제 동일한 스테레오 경로인지 재검사한다. 초기 엔진 재시도는 첫 PCM 전 2초/최대 2회로 제한한다. 계속 실패하면 JSON의 `audioEvents`에 정확한 알림/원인 코드를 남긴다. 실제 iPhone에서 재검증이 필요하다.

## Mac에서 실제 아이폰에 설치

1. 사용하는 아이폰의 iOS를 지원하는 Xcode를 설치한다. 앱 최소 지원은 iOS 17이지만 **iOS 27 아이폰은 해당 기기를 지원하는 Xcode가 필요**하다.
2. 이 폴더의 `SoundFieldStereo.xcodeproj`를 Xcode에서 연다. 로컬 Swift 패키지만 사용하므로 외부 라이브러리 다운로드나 npm 설치는 필요 없다.
3. SoundFieldStereo target → Signing & Capabilities → Team에서 자신의 Apple 계정을 선택한다. Bundle Identifier는 자신이 사용할 수 있는 고유 값으로 바꾼다. 저장소에는 인증서·개인 Team ID를 넣지 않는다.
4. 아이폰을 연결하고 신뢰·개발자 모드를 설정한 뒤, 실행 기기로 아이폰을 선택하여 Run(⌘R)한다. 개인 계정 설치의 유효기간 등 서명 정책은 Xcode 안내를 따른다.
5. 앱에서 **후면 → 카메라·수음 시작**을 누르고 카메라·마이크를 허용한다. 아이폰을 세로로 고정한다. 실제 PCM 2채널이 아니거나 stereo 선택이 적용되지 않으면 분석을 시작하지 않는다. 영상 없이 비교하려면 **측정 상세 → 스테레오 수음 시작**을 사용한다.

## Mac 없이 Windows에서 설치

Mac CI가 `SoundFieldStereo-unsigned.ipa`를 생성한다. 소스 프로젝트가 아니라 실제 Release/iphoneos 실행 파일이며, 개인 서명 후 설치할 수 있다. Safari에서 링크를 누르는 것만으로 설치되는 파일은 아니다. 사용자 기기의 설치 성공 여부는 별도 확인한다.

1. [Sideloadly 공식 사이트](https://sideloadly.io/)에서 Windows 설치 방법을 따른다. 해당 도구는 Windows용 iTunes·iCloud의 Apple 직접 배포 버전을 요구하므로 기존 설치 상태를 먼저 확인한다.
2. 아이폰을 USB로 연결하고 아이폰에서 이 컴퓨터를 신뢰한다.
3. Sideloadly에서 아이폰을 선택하고 `SoundFieldStereo-unsigned.ipa`를 넣는다. 자신의 Apple 계정으로 서명·설치한다. 비밀번호·인증코드는 해당 프로그램에서 직접 입력하며 채팅/저장소에 넣지 않는다.
4. 아이폰 설정의 일반 → VPN 및 기기 관리에서 개인 개발자를 신뢰하고, 개인정보 보호 및 보안 → 개발자 모드를 켠다. 재시작·확인 안내가 나오면 따른다.
5. 앱을 열어 아래 실기기 검사를 진행한다. 무료 계정 서명은 7일이므로 도구의 갱신 기능이나 재서명을 이용한다. 유료 Apple Developer 가입은 이 개인 설치 경로의 필수 조건이 아니다.

회사 앱에서 경험한 링크 설치는 대개 Enterprise 서명/프로비저닝을 이용한다. 이 앱에는 현재 그런 배포 자격이 없으며, 일반 IPA 파일에 다운로드 링크를 만드는 것만으로 같은 설치가 되지는 않는다. 회사용 내부 배포 계정이 있을 때 사용하는 별도 경로다. [Apple의 기업 앱 설치 안내](https://support.apple.com/ko-kr/118254).

## 연속 관측과 회전 기록

- 구간별 시간차를 최근 2초/최대 240개까지 보관한다. 최근 0.5초의 중앙값과 MAD 기반 산포를 갱신해 단발 이상치 영향을 줄이고 변화에 따라 오래된 관측을 버린다.
- 적어도 3개·150ms 관측과 60% 유효 비율을 요구한다. 최신 프레임이 무음/복제/모호하면 누적값도 보류하며, 새 프레임이 350ms 이상 없으면 다음 100ms 갱신에서 추정값을 숨긴다. 중지·재시작 시 과거 숫자를 현재 추정으로 남기지 않는다.
- 산포는 신호 지연의 흔들림이다. 물리 위치의 정확도·신뢰구간이 아니며 같은 자세의 관측 횟수를 독립 센서 수로 환산하지 않는다.
- 수음 중 Core Motion을 50Hz로 읽고 PCM 중간의 host 시각에 가장 가까운 자세를 최대 60ms 허용 오차로 대응시킨다. quaternion과 실제 시각 차를 JSON에 남긴다. 센서 간 하드웨어 동기화 검증이 아닌 소프트웨어 시각 대응이다.
- 회전은 시작 자세 대비 변화량이다. 자기 북쪽·음원 방위·이동거리·위치가 아니다. 회전 센서가 없거나 시각이 오래되면 자세를 비워 두고 수음 분석은 계속한다. 카메라/AR 위치 추적·음향 교정·위치 관측 융합은 아직 연결하지 않았다.
- JSON schemaVersion은 4다. 최근 통계·자세·오디오 알림 원인과 실제 입력의 항목별 검사·시작 조작 경로를 포함하며 PCM/녹음 파일은 포함하지 않는다.

## 첫 실기기 검사

- 블루투스/USB 오디오 장치를 분리하고 조용한 실내에서 시작한다. 기본 화면의 통합 버튼은 카메라와 내장 마이크를 함께 사용한다. 카메라 없이 검사하려면 시작 전에 측정 상세에서 스테레오 수음만 시작한다.
- 휴대폰을 고정하고 약 0.5~1m의 왼쪽·정면·오른쪽에서 종이 비비기 등 광대역 소리를 낸다. 각 위치에서 `소리 위치 기록`을 누른다. 표시는 사용자가 선언한 위치이며 자동 교정이나 정답 좌표 입력이 아니다.
- 좌우 레벨·활성 여부·복제 의심·지연 부호가 어떻게 바뀌는지 확인한다. 양수 지연은 오른쪽 신호가 늦음, 음수는 왼쪽이 늦음이다. 전면에서도 반복한다.
- `진단 JSON 공유`로 보고서를 저장/공유한다. 공유 직전에 수음을 중지한다. 보고서는 통계·요청값·실제 포맷·선택 소스·OS 버전만 포함하며 **원음·영상·장치 ID는 포함하지 않는다**.
- 중지/재시작, 권한 거부 후 설정 변경, 잠금·앱 전환, 전화 인터럽트, 헤드셋 연결 시 중지와 마이크 해제를 확인한다. 자동 재개하지 않는다.

2채널 수신 + 양쪽 활성 + 비복제는 다음 교정 단계에 필요한 관찰이다. 물리 센서 독립성·무처리 PCM·하드웨어 동기화의 증명은 아니다. 고정 거리의 여러 방위·주파수·전후면에서 지연 편향과 재현성을 확인한 뒤 위치 엔진 연결 여부를 결정한다.

## 계산과 범위

- 같은 AVAudioPCMBuffer의 실제 2채널 Float32를 사용한다. 강제 2채널 변환·모노 복제·스피커 재생은 없다. 권장 48kHz와 실제 샘플률을 구분한다.
- 평균 제거 후 정규화 상호상관의 절댓값을 ±1ms에서 검색한다. 정수 샘플 분해능은 48kHz에서 약 20.83µs. GCC-PHAT 위치 SDK와 별도의 입력 진단이며 서브샘플 정확도를 주장하지 않는다.
- 한쪽 AC 무음, 포화, 동일/이득 배율/극성 반전 복제, 낮은 상관, 반복 피크, 검색 경계는 지연 값을 숨긴다. 상관 0.35·피크 차 0.08·복제 잔차 1e-5는 초기 휴리스틱이며 실측 신뢰구간이 아니다.
- ±1ms는 진단 검색 범위다. 아이폰 물리 마이크 간격에서 유도한 범위가 아니다. 이 범위 밖 신호와 반사 환경에서 정확한 지연 검출은 보장하지 않는다.
- 처리 중 새 버퍼는 건너뛰고 개수를 남긴다. PCM 대기열은 한 개로 제한한다. `analyzedTimelineGaps`는 분석한 버퍼 사이의 sampleTime 불연속이며 처리 건너뛰기와 실제 입력 중단을 구분하지 않는다.
- `physicalMicrophonesVerified`, `hardwareSynchronizationVerified`, `localizationEnabled`는 항상 false다. 지연을 각도·거리로 환산하거나 임의 마이크 배치로 기존 위치 엔진에 넣지 않는다.

Apple 스테레오는 데이터 소스/빔포밍을 사용해 생성될 수 있다. `.measurement` 모드는 primary microphone을 사용하므로, raw 스테레오를 준다고 가정해 선택하지 않는다. 앱은 `.record` + `.default` + `.stereo` + 세로 입력 방향을 사용한다.

## 검증

Mac에서 `bash scripts/verify.sh`를 실행한다. Swift 패키지 단위 검증, 서명 없는 Release 기기 빌드, DEBUG 합성 입력의 UI 검증을 수행한다. 실제 시작 버튼은 권한 확인 전에는 수음하지 않는다. 합성 모드는 `#if DEBUG` 내부에만 있고 화면과 JSON에 명확히 표시된다.

검증 결과와 실패 수정 기록은 저장소 루트 `DEVLOG.md`, `docs_canonical/TESTING.md`에서 관리한다. GitHub Actions의 **Native iOS**가 동일 절차를 실행하고 로그·xcresult·화면을 보관한다.

빌드 2의 기준 코드는 `95cda61`이다. [Mac CI](https://github.com/doroper98/sound_detection/actions/runs/35725200763)에서 Swift 25/25, UI 11/11, Release 기기 빌드와 IPA 포장 PASS. [영구 결과](../../docs/reports/2026-09-22-native-camera-routefix-verification.json)에 해시와 실기기 미검증 범위를 보존했다. 기존 Sideloadly 사용자는 전달받은 새 `SoundFieldStereo-build2-unsigned.ipa`를 선택하고 같은 Apple 계정·번들 설정으로 덮어쓴 뒤 앱 하단 **빌드 2**를 확인한다.
